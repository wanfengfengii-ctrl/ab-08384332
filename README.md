# 标记布局重建工作台（超声导轨校准夹具）

反射标记标签脱落后，测量仪只保留全部两两间距的**无序多重集**。本工作台在浏览器中由该多重集
**完整搜索**与之一致的标记布局（经典 turnpike / partial digest 重建），全程纯前端运行，
**不调用任何业务后端**。

## 功能

- 标记数量 `n`：4–18，位置互异；间距恰好 `n(n−1)/2` 个，非负、最多三位小数。
- 计算统一按 `×1000` 缩放为整数，多重集**保留重复项次数**。
- 求解器完整搜索与多重集**精确一致**的布局；最左点平移至 0；**镜像视为同一布局**。
- 三种裁决：
  - **无解**：不存在一致布局；
  - **唯一解**：给出规范最小布局；
  - **多个非镜像布局**：给出规范最小布局与第二份**歧义见证**。
- 结果区：**共用刻度尺**对照候选位置 + **逐距离消耗记录**（悬停行可在尺上高亮点对）。
- 修改任意输入自动清除旧裁决与求解进度。
- 支持文本框编辑、文件导入（纯文本 / CSV / JSON 数组）与内置示例。

## 本地开发

```bash
npm ci
npm run dev        # 开发服务器
npm run test       # 求解器单元测试（vitest）
npm run typecheck  # TypeScript 类型检查
npm run build      # 生产构建 → dist/
```

## 验收

```bash
./verify           # 或 npm run verify
```

`verify` 是可执行验收服务，依次执行：环境检查 → 依赖安装 → 类型检查 → 单元测试 →
生产构建 → Docker 交付物静态检查 →（检测到 Docker 时）镜像构建与容器健康检查。
任一必需步骤失败即以非零码退出；`VERIFY_PORT` 可指定容器端到端检查的宿主机端口（默认 18080）。

## Docker 部署

```bash
# 方式一：Docker Compose（宿主机端口可配置，默认 8080）
WEB_PORT=9000 docker compose up --build -d

# 方式二：Docker
docker build -t turnpike-workbench .
docker run -d -p 8080:80 turnpike-workbench
```

- 镜像为多阶段构建：`node:22-alpine` 构建静态资源，`nginx:1.27-alpine` 托管，无后端进程。
- 健康检查：`GET /healthz` 返回 `200 ok`（Dockerfile `HEALTHCHECK` 与 Compose `healthcheck` 均已配置）。
- 宿主机端口：Compose 通过环境变量 `WEB_PORT` 配置（`${WEB_PORT:-8080}:80`）。

## 输入格式

- 标记数量 `n`：4–18 的整数。
- 间距多重集：非负十进制数，最多三位小数（如 `12`、`0.5`、`12.345`），
  以空白、逗号（含中文逗号 `，`、顿号 `、`）、分号分隔；数量必须恰好等于 `n(n−1)/2`。
- 文件导入支持 `.txt` / `.csv` / `.json`（JSON 数组如 `[1, 2.5, 3]`）。

## 裁决语义与算法

- 输入解析后立即缩放为整数（`×1000`），多重集以「距离 → 次数」存储。
- 回溯搜索：最大距离即宽度 `width`，端点 `0`、`width` 必在布局中；每步取剩余最大距离 `d`，
  候选新点为 `d` 或 `width − d`，仅当其到所有已放置点的距离都能从多重集中消耗时递归放置。
- 每个完整布局经规范化（最左点为 0，镜像取字典序最小）后去重；
  搜索穷尽（或达到记录上限）后按规范形字典序给出**规范最小布局**与**第二份歧义见证**。
- 无解 / 唯一 / 多解分别对应零个、一个、多个非镜像规范布局。
- 求解在 Web Worker 中执行，带节点预算保护；超预算视为「求解中止」而非裁决。

## 项目结构

```
├── index.html
├── src/
│   ├── App.tsx                  # 应用状态与 Worker 编排
│   ├── components/              # 输入面板 / 结果面板 / 共用刻度尺 / 消耗记录表
│   ├── solver/
│   │   ├── parse.ts             # 解析、校验、×1000 整数缩放
│   │   ├── turnpike.ts          # 完整回溯搜索、镜像折叠、消耗记录
│   │   └── *.test.ts            # vitest 单元测试
│   └── worker/solver.worker.ts  # 本地求解 Worker（无网络访问）
├── Dockerfile                   # 多阶段：构建 → nginx 静态托管（含 HEALTHCHECK）
├── docker-compose.yml           # 可配置宿主机端口 WEB_PORT + 健康检查
├── nginx.conf                   # /healthz 健康检查端点 + SPA 回退
└── verify                       # 可执行验收服务
```
